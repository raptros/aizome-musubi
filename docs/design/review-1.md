# Musubi design review — independent critique

Reviewed the six requested HTML-rendered mockups (audio Night/Day, MIDI Night, mixer Night, effects Night, graph Night). These are not kit renderings or performance measurements. Findings below distinguish source-backed constraints from proposed implementation choices.

## Blockers

1. **Make matrix partial repaint implementable with the actual widget API.** What: The proposal combines a custom `Widget` with hover/focus as `parts`, but `CanvasEl::parts` is a builder for the separate `canvas(...)` element; `Widget::parts` returns *named inspection rectangles*, not draw hashes. A custom widget does not acquire canvas-part damage by implementing `Widget::parts`. Why: `proposal.md:49`; `crates/aizome-kit/src/widgets/interact.rs:505-525,528-580`; `crates/aizome-kit/src/widget.rs:223-233,360-368`. The intended crosshair update can therefore leave stale rows/columns if the scroll offset and hover/focus are omitted from the drawing hash without explicit damage. Fix: implement `PatchMatrix` as a custom widget with state-held offsets, `Widget::hash` for structural/visible-cell data and `EventCx::invalidate_rect` for the old/new row, column, focus and cell regions; implement `Widget::parts` separately for named hit-test/inspection rectangles. Or use a canvas element and its hash-based parts but then supply scrolling through a separate custom parent widget; prove partial damage with `Harness::check_frame_exact`.

2. **Define the coupled two-axis scroll geometry before promising fixed headers.** What: One `cx.scrolled` call moving the whole grid in x and y with both header bands marked `fixed` will not move the column labels horizontally or row labels vertically; moving those headers as ordinary content instead makes them drift off their fixed axis. Why: `proposal.md:29-30,49`; `crates/aizome-kit/src/widget.rs:524-532`; `crates/aizome-kit/src/tree.rs:284-314` (`fixed` means damage/repaint, not a separately translated axis); `crates/aizome-kit/src/widgets/scroll.rs:397-427` scrolls a single child. Fix: model four clipped regions (corner, column header x-only, row header y-only, body xy); calculate scroll extents after group collapse/filter/pairing; use separate disjoint pixel-scroll regions for body and each header, or explicitly invalidate and redraw the headers, with horizontal and vertical hit tests using the same offset mapping. Exercise independent/diagonal scrolling and scale changes with exact-frame tests.

## Major

3. **Include an unambiguous link-legality and observation contract in the matrix phase.** What: The proposal offers cells for media pages, UMP conversion, pair clicks and pending links but never specifies validation, error/permission handling, duplicate links or partial pair failure. Why: `proposal.md:33-35,51-53`; `r1-graph.md` §§1,2,5,6: per-port classification, optional `format.dsp`, EnumFormat alternatives, output-to-input global IDs, negotiation and potentially multiple Links per pair. An unmatched format or rejected half of a pair cannot be treated as a successful toggle. Fix: index actual Links sparsely by ordered global-ID pair; classify each Port using format/EnumFormat with unknowns disabled; permit only valid direction and compatible negotiated formats; preflight UMP↔MIDI1 explicitly and confirm conversion/semantic loss; track both per-channel commands and observed Link states, show partial/error, and undo only links actually created or removed. Preserve unresolved out-of-order globals until their parents arrive and reset IDs/pending commands on epoch change (`r1-graph.md` §§4,6,7).

4. **Specify identity and provenance for routing, undo and saved setups.** What: `device/node/port names; never runtime ids or serials` is too narrow for duplicate hardware and nonunique client streams, and undoing a WirePlumber-created link cannot be guaranteed to stick. The proposed `Keep it disconnected` exclusion only adds an app-side record; it does not stop WirePlumber from re-linking. Why: `proposal.md:46,69,76`; `r1-graph.md` §§1,3,5: runtime IDs are required for current Link create/destroy, serial/bus path can distinguish devices, policy targets and reconnects streams, and exclusive rules can race policy. Fix: use global IDs plus epoch *only for live actions*; persist composite identity (device name plus serial/bus path when available, node machine name, direction, port name, sequencer-client identity) with explicit duplicate/missing match resolution. Track user-intent and observed Link separately; distinguish manual from policy-managed deletion in the UI, disclose relink on undo/disconnect, and provide a tested policy-compatible way to suppress/repoint auto-targets before offering persistent exclusions or Exclusive. Make activation/deactivation, pin/unpin, auto-pin and removal-on-deactivate semantics explicit rather than silently inheriting qpwgraph expectations (`r1-graph.md` §3).

5. **Reconcile Pulse and native strips by a verified identity, not display names.** What: The claim of exactly one writer per volume control lacks a mapping from Pulse sink/source/stream indices to PipeWire node IDs; two identically labelled streams, a profile switch, or an epoch reset make name-based routing unsafe. Why: `proposal.md:60,73-76`; `crates/aizome-sys/src/audio.rs:145-179,200-225,329-415` exposes Pulse indices and no graph global ID; `r2-mixer-effects.md` §§1-3,8 warns that Node Props and Device Route volume differ. Fix: specify a verified bridge identity from Pulse properties to the current graph object, reject ambiguous matches and reset on server reconnect; mark Pulse-owned devices/streams as Pulse-only for writes, allow native `Props.channelVolumes` only on proven native-only writable nodes, and read back observed gain/permission. Explicitly distinguish Pulse fractions, SPA linear gain and cubic slider values; give per-channel faders a real write path rather than assuming the existing overall-volume calls support them.

6. **Make each effects chain controllable, persistent and safely bypassable.** What: One helper started/stopped by Musubi is simultaneously claimed to outlive the GUI; no startup-at-login or independently persisted enable/disable is defined. Restarting that helper on every released edit drops *all* its chains, including unrelated ones; the illustrated input-chain type also exceeds the scoped virtual-output EQ recipe. Why: `proposal.md:64-66`; `r2-mixer-effects.md` §7 (filter-chain capture/playback streams, unverified live `Props.params`, helper ownership and restart semantics). Fix: ship an explicit enabled-state user unit and reliably resolved generated config path, start at login for enabled chains without the GUI, observe helper and both stream nodes, and define failure/target-missing/bypass behavior. For v1 choose a complete stereo virtual-sink EQ only; if one helper owns multiple chains, batch writes and warn of interruption to every enabled chain, or isolate chains into independently restarted units. Treat live parameter control as unavailable until a write/readback test proves the exact POD target and shape.

7. **Separate graph runtime override from restart defaults.** What: The single `Keep after restart` switch appears to persist whichever rate/quantum is displayed, including Automatic, but `clock.force-* = 0` at runtime and `default.clock.*` in daemon config are different operations; clearing a forced override must not silently write a forced default. Why: `proposal.md:68`; `r2-mixer-effects.md` §6. Fix: expose effective rate/quantum separately from forced overrides, make Auto explicitly clear both runtime force keys and any app-owned persistent defaults, and persist only intentional numeric defaults with clear semantics for a running graph versus the next PipeWire start. Handle metadata write permission and absent Profiler; label sampled ERR as errors/xruns (not guaranteed xruns), and do not advertise a global xrun reset (`r2-mixer-effects.md` §§6,8; `mock/graph-night.png` Reset Counters).

8. **Ship the patch matrix first, rather than an empty collection of system pages.** What: The present v1 implicitly includes routing, mixer, meters, effect hosting, devices, graph diagnostics, setups, MIDI2 and video at once; the plan has no shippable dependency boundaries, and listing optional empty features as working pages is misleading. Why: `proposal.md:9-19,54-84`; `r1-graph.md` §§5-7 and `r2-mixer-effects.md` §§5,7-8 describe different backends, probes and service lifetimes. Fix: Phase 1 ship a *complete* Audio + bridged/native MIDI matrix with live connect/disconnect, legality/error feedback, pair/mono/keyboard/scroll/inspector, safe policy-link explanation and packaging, Night/Day goldens plus real graph tests. **The matrix is mandatory in phase 1**; a mixer without it is not this patchbay. Phase 2 ship complete Pulse/native mixer, per-visible-strip metering and device profiles/routes. Phase 3 ship graph diagnostics/settings and one fully supervised stereo virtual-sink EQ, with each page withheld until its runtime contract works. Phase 4 ship persisted setup reconciliation/Exclusive, optional ALSA-sequencer-native routing, MIDI2 cross-kind routing and video only when each is integrated end-to-end. Show only implemented pages, not placeholders or perpetual empty states.

9. **Provide a screen-reader/keyboard alternative for every matrix cell.** What: One canvas/widget focus with arrows and a status-bar sentence is not a semantic grid; assistive technology cannot enumerate or activate the individual connections, and the visible 18pt squares need an explicitly 24pt hit box. Why: `proposal.md:33,40-44`; `crates/aizome-kit/src/widgets/interact.rs:607-609` defaults to one `Canvas` role; `crates/aizome-kit/src/widget.rs:128-178` offers Table/Cell/ColumnHeader, label/value/actions only per element/widget; `docs/apps.md:50-63` requires keyboard reachability and 24pt targets. Fix: maintain keyboard focus by stable port-pair identity with Home/End/Page navigation, auto-reveal in both axes, visible focus/selection and full accessible row/column/link/action readout; provide a virtualized inspectable table or a selected-route list with real labelled controls/semantics and tab navigation, including pair-half actions and collapsed-group counts. Hit-test the whole 24pt pitch, not only the drawn square, and scale controls with kit appearance metrics.

10. **Prove the 200×200/4 ms budget with a concrete sparse frame design.** What: Only drawing visible cells and coalescing backend messages does not bound per-frame model rebuilding, hit testing, text outlining, header repaints or allocations. Why: `proposal.md:49,74,80-82`; `r1-graph.md` §7 requires sparse link indices and visible-row/column virtualization; `docs/apps.md:56-63` sets 4 ms; `sukumo/crates/sidestep-ui/src/canvas.rs:727-756,781-814` sends rotated non-colour glyphs down an outline/path rasterization route rather than the cached upright glyph fast path. **Rotation is supported** (`canvas.rs:415-417,727-756,781-814`; `sidestep-engine/src/raster/ops.rs:240-243,509-511`), so a 45° text fallback does not remove that cost. Fix: precompute sorted visible-port ranges and column/row prefix offsets, use sparse per-pair link lookup, cache label layouts/path operations where possible, clip before shaping/drawing and update only damaged bands; measure 200×200 interaction at Night/Day and 1×/2× with `SIDESTEP_FRAME_STATS=1`, documenting exceptions. Test focus, hover, diagonal scroll and filtered/group-changed frames with `Harness::check_frame_exact`.

* **Implement the vertical fader and segmented meter as new widgets, not kit sliders/meters.** What: The mixer drawing assumes a vertical, per-channel, cubic/dB fader and stereo segmented peak meter, but the existing `slider` is horizontal (its layout is 80pt minimum width, pointer position uses x, and the track draws along x) and `meter` is a 14pt-tall solid bar with one colour/one averaged accessibility value. Why: `proposal.md:57-61`; `crates/aizome-kit/src/widgets/controls.rs:934-1184,2054-2145`; `docs/kit.md:146-157`. Fix: keep app-local `Fader` and `LevelMeter` widgets with top-to-bottom dB mapping (zero = −infinity), measured peak-hold and overload thresholds per channel, explicit mute/linked-channel behavior, 24pt-or-larger hit regions, keyboard Page/Home/End and accessible per-channel labelled slider/meter ranges; use the kit theme and drawing primitives. Test pointer/key mapping, scale/Night/Day, muted and unavailable values with Harness.

* **Preserve routable destinations under filtering and make topology inspectable.** What: One search narrows *both* axes to names matching the same query, so searching for a source such as Scarlett hides unlike destinations such as Discord and makes their cells impossible to select. Also, a page called `Graph` shows quantum/profiler data rather than any node/link topology, while qpwgraph/Helvum users expect to inspect whole routes outside a dense matrix. Why: `proposal.md:13,41,68`; `mock/audio-night.png` has Scarlett and Discord on opposite axes; `mock/graph-night.png` shows only clock and driver rows; `r1-graph.md` §3 describes qpwgraph/Helvum routing canvases. Fix: add independent From/To searches (or a mode that filters one axis while retaining all legal peers), with visible hidden-link counts and a clear-filter action. Rename the existing diagnostics page `Clock & performance` and provide a selectable current-route list/node overview (selected port plus complete goes-to/from links, upstream and downstream) rather than promising a graph canvas silently; ensure every route can be located via search/inspector in phase 1.

## Minor

11. **State strict stereo grouping and collapsed-cell behavior.** What: `FL/FR of one node` alone does not enforce shared direction, port group, media type and base label; collapsed groups replace ports with a count but still invite click/drag toggles without saying which original links they affect. Why: `proposal.md:33-37`; `r1-graph.md` §4 Stereo collapse. Fix: enforce all pairing predicates in R1 (including AUX exclusion), expose mixed mono/stereo cells as explicit single-channel links, and make collapsed count cells informational or require expansion before edits. Define expand/collapse keyboard action and persistence keyed by stable group identity.

12. **Make drag-paint predictable and reversible.** What: Dragging from a connected cell in an auto-linked row can disconnect many links; diagonal drag overlaps normal painting, and revisiting cells or moving past group gaps is not defined. Why: `proposal.md:38,46`; `r1-graph.md` §5 on WirePlumber relinking. Fix: define a gesture mode (paint vs explicit diagonal tool/modifier) before the first change; show preview and connected/policy ownership, apply each visited pair at most once only after crossing a threshold, skip illegal/collapsed cells, and group observed successful operations in one undo transaction. Confirm destructive disconnect-all and Exclusive separately.

13. **Make the group and MIDI page model consistent with the bridge.** What: Device-first grouping can swallow separate sequencer clients if a bridge gets a device association; mock MIDI already shows KeyLab, Digitakt and MIDI Through as distinct groups, while optional `ALSA Sequencer` sidebar implies the bridge ports might be duplicated as separately linkable native ALSA endpoints. Why: `proposal.md:13,29,51-53`; `r1-graph.md` §§2,4,5 and `mock/midi-night.png`. Fix: recognize a verified ALSA MIDI bridge *before* ordinary device grouping; subdivide by explicit sequencer-client properties when present and show an unclassified bridge fallback otherwise. If a native ALSA page is chosen, label its `aconnect` links as a separate graph with separate IDs/undo; never repeat PipeWire bridge Links there.

14. **Specify virtual-strip meter scope and MIDI activity instrumentation.** What: A 24-stream cap leaves visible strips unmetered without an indicator; `~30 Hz` UI sampling alone does not bound RT wakes, and an inspector promises MIDI channel LEDs without a defined event-monitoring source. Why: `proposal.md:43,61`; `r2-mixer-effects.md` §5 says each native meter is a graph stream and RT callbacks must avoid allocations/GUI wakes; `crates/aizome-sys/src/meter.rs:5-10,34-45,97-135` opens a thread/Pulse connection per meter. Fix: meter only the currently visible/selected strips in one native loop, prioritize selected/main within the cap and mark the rest inactive; publish snapshots on UI cadence, stop on page hide/core loss, and specify and cost a genuine MIDI monitor before promising per-channel LEDs (otherwise omit those LEDs from the shipped page).

15. **Finish desktop packaging and headless acceptance criteria.** What: A binary/app ID and fake `Backend` do not specify desktop entry/icon, single-instance socket semantics for the background reconciler, installation paths or text-input-safe shortcuts. Why: `proposal.md:3,14-19,70-82`; `docs/apps.md:35-63`; `docs/kit.md:397-415,578-629`; `crates/aizome-kit/src/testing.rs:1475-1495`. Fix: require `org.aizome.Musubi.desktop` with GenericName/Keywords/Exec/Icon, generated SVG, one-instance handoff even with no window, state/data/config in their respective XDG directories, standard menus and palette commands, Night/Day real kit goldens for each shipped page, and null-backend state tests plus private PipeWire/WirePlumber tests. Include matrix parts/semantics in the VM inspector, guard type-to-filter and shortcuts while a field has focus, and add 1×/2× scale and large-appearance snapshots. HTML mockups do not satisfy golden acceptance.

## Open questions for the user

- D1: Keep Musubi / Patchbay and the proposed app ID, or choose another shipped name?
- D2: Approve the phased order above, with the complete matrix mandatory in the first public release? Which media pages besides Audio and MIDI are launch requirements?
- D3: Is a *separate native ALSA sequencer* graph really required when PipeWire MIDI bridge clients already appear on MIDI?
- D4: Default From-rows/To-columns (as drawn), or swapped, and should this be remembered per media page?
- D5: Should persistence be opt-in only, and are policy-changing exclusions/Exclusive acceptable given WirePlumber auto-routing conflicts? What is the intended quit, hide and logout behavior for the reconciler?
- Does Effects v1 need input/voice EQ as pictured, or is one correctly supervised stereo virtual-sink EQ the initial scope? Are momentary gaps while editing acceptable?
- Are CV/control and unknown formats to have a read-only inventory, a routable advanced page with safety warnings, or explicitly no launch support? (`r1-graph.md` §§3,5.)
